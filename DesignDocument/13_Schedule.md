# 13. 開発スケジュール・体制・コスト見積（Execution Plan）

> 改訂：2026-10-22。方針転換メモ（`DirectionChange_20261022.md`）の決定事項 D1〜D16 と 2.10 共通契約を反映した。

## 13.1 方針

- 個人開発で「開発者自身の就活・転職で実際に使える状態」（事業ゴールのフェーズ1。D14）を最短で作る
- 運営費はほぼ0円を守る（各サービスの無料枠内で運用する）
- フェーズごとに「成果物（Deliverables）」を固定し、完了条件を明確にする
- スケジュールは“理想”ではなく“バッファ込みの現実ライン”で組む
- 既存の Go バックエンドは Clean Architecture で層が分かれているため、内側（Domain / Usecase）を活かし、外側（Infra）の差し替えを中心に移行する

---

## 13.2 体制

- 開発者：1名（フルスタック）
  - 役割：
    - 要件定義・設計
    - Go BFF / API の実装
    - DB 設計（Neon / PostgreSQL）
    - プロンプトテンプレートと解析の設計
    - iOS アプリ（SwiftUI）の実装
    - テスト・リリース（実機検証）
- 外注/協力：なし（MVP 時点）
- デザイン：
  - Figma で最低限のワイヤー + UI 設計
  - iOS 標準の UI 部品を優先し、デザインシステムは後回し

## 13.5 コスト見積（MVP）

### 固定費（月）

- Cloud Run：$0（無料枠内を想定。超えそうになったらコストガードが API を止める。12.12）
- コストガード（Cloud Scheduler 1 ジョブ、Cloud Run、Pub/Sub、Cloud Monitoring の読み取り、予算通知）：$0（無料枠内を想定）
- Artifact Registry / Secret Manager：$0（クリーンアップポリシーと不要なバージョンの破棄で無料枠内に保つ。12.12.7）
- Neon：$0（無料枠内を想定）
- Firebase Auth：$0（無料枠内を想定）
- GitHub Actions：$0（無料枠内を想定。macOS ランナーは消費が大きいため、`ios/` 変更時のみ実行する。14.5）
- ドメイン：任意（共有リンクを独自ドメインにする場合のみ。Cloud Run の既定 URL でよければ不要）

※ 各無料枠の上限は公式で要確認

### 変動費

- LLM API：$0（API を呼ばない。D7）
- 決済手数料：なし（課金しない。D14）

### 配布時の費用

- Apple Developer Program：年 $99（フェーズ2で TestFlight 配布を始める時点で加入）

### 初期開発コスト感

- フェーズ1（自分の iPhone のみ）：ほぼ0円
- フェーズ2 以降：年 $99 ＋ 無料枠を超えた分

## 13.6 リスクとバッファ

- リスク
  - 外部AIの出力の揺れ（形式行を出さない、目印が崩れる）→ 解析の許容範囲を広く取り、プレビューでの手動修正を前提にする。実際の出力を回帰テストに追加する
  - 無料枠の条件変更（上限の縮小、有料化）→ 月1回、各コンソールで使用量を確認する。移行しやすいよう、Infra 層で差し替え可能にしておく
  - 攻撃や暴走による Cloud Run の利用量の急増 → 最大インスタンス数 1、コストガードの自動停止、予算通知の3段で請求を抑える（12.12）。停止中もキャッシュで閲覧できる
  - 無料 Apple ID の制約（7日ごとの再インストール、Sign in with Apple・iCloud・プッシュ通知が使えない）→ 再インストールの手順を README に残す。配布開始時に Developer Program に加入する
  - Swift / SwiftUI の学習コスト → iOS 標準の UI 部品を優先し、凝った UI は後回しにする
  - Neon のコールドスタートによる待ち時間 → iOS の読み取りキャッシュを先に表示する（D16）
  - 既存コードの移行で層の境界が崩れる → `arch_check.sh` を CI で必ず実行する
- バッファ戦略
  - フェーズ3、5に各 +1週間の余裕を見ておく
  - MVP スコープ削減候補を事前に決めておく
    - 例：ダッシュボード要約（`summary_generate`）、スキャン PDF・画像の OCR を次フェーズに回す

## 13.7 この章の凍結事項

- 約12週間で、開発者自身が実際に使える状態（フェーズ1のゴール）を目標にする
- 順序は「設計改訂 → バックエンド移行 → CRUD API → AI連携 → 共有リンク → iOS アプリ → 実機検証」
- 運営費は月額ほぼ0円を目標にし、避けられない費用は配布時の Apple Developer Program（年 $99）のみとする
- 本番反映の前に、12.5 のリリース前チェックを必ず通す
