# 9. セキュリティ・プライバシー・法務

> 改訂：2026-10-22。方針転換メモ（`DirectionChange_20261022.md`）の決定事項 D1〜D16 と、2.10 共通契約を反映した。決済（Stripe）・クレジット・Supabase RLS に関する節は廃止した。

## 9.1 方針（最上位）

- 本プロダクトは職歴・面接ログ・志望動機などの高感度な個人データを扱うため、最小権限・最小保存・監査可能性を重視する
- データにアクセスできるのは Go BFF だけとし、認可はすべて BFF のアプリ層で強制する（D6）
- 運営側のサーバーは外部AIサービスにデータを送らない。外部AIへの受け渡しは、ユーザー自身の操作で行う（D7）
- 保存するデータは必要最小限にする
  - プロンプトの全文と、貼り戻した回答の生データは保存しない（D13）
  - 企業研究資料はファイル本体を保存せず、抽出テキストだけを保存する（D11）
- 決済は扱わない（D14）。カード情報などの決済データを一切持たない

---

## 9.2 データ分類（取り扱いレベル）

### 9.2.1 最高機密（漏洩時のインパクトが最大）

- 面接ログ（質問・回答・評価・改善案）
- 自己資産（経歴、成果、強み・弱み、エピソード）
- 志望動機メモ、選考状況
- ES の下書き・完成文（志望動機・自己PR など）
- 企業研究資料の要約・メモ（ユーザーの解釈を含む）
- 共有リンクのスナップショット（`share_links.snapshot`）

### 9.2.2 機密

- ユーザー識別子（`users.id`、`firebase_uid`）、メールアドレス
- 企業DB（一般公開情報とユーザーのメモが混在するため注意する）
- 企業研究資料の抽出テキスト（公開情報由来でも、ユーザーが選んだデータとして扱う）
- AI連携のメタデータ（`prompt_sessions`：use_case、対象 ID、`input_refs` の ID 群）

### 9.2.3 秘密情報（システム）

- `DATABASE_URL`（Neon の接続文字列）
- 共有リンクの生トークン（発行時の応答でのみ扱い、保存しない）

---

## 9.3 認証（Firebase Auth）

- 認証は Firebase Auth（メールアドレス＋パスワード）で行う（D5）
- クライアントは `Authorization: Bearer <Firebase ID トークン>` を BFF に付ける
- BFF の認証ミドルウェアは、ID トークンを次の手順で検証する（2.10.3）
  - Google の公開鍵で署名を検証する（公開鍵はキャッシュし、`Cache-Control` に従って更新する）
  - `aud` が Firebase プロジェクト ID（`FIREBASE_PROJECT_ID`）と一致すること
  - `iss` が `https://securetoken.google.com/<プロジェクトID>` であること
  - `exp` が未来、`iat` が過去であること。`sub`（= `firebase_uid`）が空でないこと
- 検証に失敗したら 401 `UNAUTHORIZED` を返す
- `firebase_uid` から `users` を取得または作成し、`user_id` を確定する。リクエストボディやクエリの user_id は信用しない
- 退会済み（`users.deleted_at` が設定済み）のユーザーは 401 として扱う
- パスワードの保存・検証は Firebase が担い、アプリと BFF はパスワードを扱わない
- クライアント側のトークン保存は Firebase SDK（Keychain）に任せる（5.5.3）

---

## 9.4 認可（アプリ層での user_id スコープ。RLS の代替）

RLS は使わない（D6、2.10.2）。代わりに、次のルールで越境を防ぐ。

### 9.4.1 実装ルール

- Repository のすべてのメソッドは `user_id` を必須の引数にとる。user_id なしでユーザーデータを読み書きできるメソッドを作らない
- すべての SELECT / UPDATE / DELETE に `WHERE user_id = $1` を付ける。ID だけで行を特定するクエリを書かない
- 関連テーブル（`asset_tag_relations` など）を操作するときは、親の行（asset・tag など）がそのユーザーのものかを、同じトランザクションの中で確認する
- 他人の行を指定されたときは、存在しない場合と同じ 404 `NOT_FOUND` を返す（存在するかどうかを漏らさない）
- `user_id` を Domain の外から受け取る経路は、認証ミドルウェアが Context に入れた値だけにする
- DB ユーザーは BFF 専用の 1 つとし、必要なテーブルへの権限だけを与える。DDL の権限はマイグレーション用のユーザーに分ける

### 9.4.2 テスト（11 章と連携）

- 統合テストで、全エンドポイントについて「ユーザー A のトークンでユーザー B のリソースを読む・更新する・削除する」と 404 になることを確認する
- 新しいエンドポイントを追加したら、この越境テストの追加を必須とする（レビューで確認する）

---

## 9.5 データ保護（通信・保存）

### 9.5.1 通信

- すべて HTTPS / TLS を必須とする（Cloud Run の HTTPS エンドポイント）
- BFF は HSTS ヘッダを付ける
- BFF と Neon の間は TLS（`sslmode=require` 以上）で接続する
- iOS アプリは ATS を有効のままにする（例外は dev の localhost だけ。5.13）

### 9.5.2 保存（サーバー）

- Neon に保存されたデータは、Neon の機能で保存時に暗号化される
- 認可はアプリ層で行う（9.4）
- 共有リンクのトークンは、SHA-256 のハッシュだけを保存する（9.7）
- バックアップとリストアは 12 章に従う

### 9.5.3 保存（端末）

- SwiftData のキャッシュと下書きは、Data Protection（`completeUnlessOpen` 以上）で保護する（5.8.4）
- ログアウト・退会・別アカウントでのログイン時に、キャッシュと下書きをすべて消す（D16）
- トークンは Firebase SDK が Keychain に保存する。アプリ独自の保存はしない

---

## 9.6 シークレット管理

- サーバーの秘匿値は `DATABASE_URL` だけとする（2.10.6）
  - Cloud Run の環境変数に、Secret Manager などのシークレットとして注入する
  - リポジトリと iOS アプリには置かない。`.env` はコミットしない
  - 漏洩時は Neon でパスワードを再発行し、Cloud Run を再デプロイする（手順は 12 章）
- `FIREBASE_PROJECT_ID`、`SHARE_BASE_URL`、`APP_ENV`、`LOG_LEVEL` は秘匿値ではない
- Firebase の設定（`GoogleService-Info.plist` の API キーなど）は、クライアントに埋め込まれる公開情報として扱う。ただし、次の制限をかける
  - Google Cloud Console で API キーの利用を iOS のバンドル ID と必要な API（Identity Toolkit など）に制限する
  - Firebase Auth で、使わないサインイン方法を無効にする
  - dev と prod でプロジェクトを分ける
- LLM の API キー、Stripe のキー、Supabase のキーは存在しない（D7 / D8）

---

## 9.7 共有リンクの安全性（D12）

- トークンは 32 バイト（256 ビット）の暗号学的乱数（`crypto/rand`）で生成し、base64url で表す（D12 の「128 ビット以上」を満たす）
- DB には SHA-256 のハッシュだけを保存する。生トークンを返すのは発行時の応答だけで、ログにも出さない
- 閲覧（`GET /s/{token}`）は認証不要とし、次を守る
  - `X-Robots-Tag: noindex`（HTML にも `<meta name="robots" content="noindex">`）と `Cache-Control: no-store` を付ける
  - `Referrer-Policy: no-referrer` を付け、リンク先の外部サイトにトークンを渡さない
  - `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; img-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'` を付け、スクリプト・画像・フォーム・外部リソース・他サイトへの埋め込みを禁止する（静的な HTML のみ。410 / 404 / 503 のページも同じ）。本文は `html/template` でエスケープして表示する
  - 期限切れ・失効は 410 `SHARE_LINK_GONE`、存在しなければ 404 を返す
  - IP 単位でレート制限をかけ、トークンの総当たりを防ぐ（9.10）
- 有効期限は 1 / 7 / 30 日から選ぶ。無期限は不可。ユーザーはいつでも失効できる
- 表示するのは、発行時点のスナップショット（セクションの `content_final`、なければ `content_draft`）だけ。ユーザー名は表示しない。企業名は、発行時に選んだ場合だけ表示する（`show_company_name` の既定値は false）
- ES プロジェクトを削除すると、紐づく共有リンクも削除する
- 期限切れまたは失効したリンクは、運用で定期的に物理削除してよい（12 章）

---

## 9.8 外部AIへの受け渡しとプライバシー（D7）

- 運営側のサーバーは、外部AIサービス（ChatGPT・Gemini など）にデータを送らない。データを渡すのは、ユーザーが共有シートやクリップボードで行う操作だけ
- アプリは、初回の受け渡し時と設定画面で、次の注意を表示する
  - プロンプトには、選んだ自己資産・企業情報・面接ログが含まれる
  - 渡したデータは、外部AIサービスの規約に従って扱われる（学習に使われる設定の場合がある）
  - 必要に応じて、外部AIサービス側の学習オプトアウトを設定することを推奨する
- データの最小化
  - プロンプトに含める自己資産と資料は、ユーザーが選んだものだけにする
  - 長い資料は、要約（`summary`）を使うよう案内する（5.10.4）
- プロンプトテンプレートには、経歴の捏造や詐称を助長しない旨の制約を明記する（4 章）
- プロンプトの全文と、貼り戻した回答の生データはサーバーに保存しない（D13）
- 貼り戻した回答はユーザー入力として扱い、BFF で通常の入力と同じ検証（文字数・形式）を行う

---

## 9.9 入力検証と取り込み

- BFF はすべての入力を検証する（必須項目、最大文字数、enum の値、ID の形式）。クライアントの検証は補助とする
- 貼り戻した回答（`/prompt-sessions/{id}/parse`）は、最大サイズを 100,000 文字に制限する（7.5.5）
- 企業研究資料の URL 取り込みは、端末側（WKWebView）で行う（D11）
  - サーバーは任意の URL を取得しないため、SSRF 対策は不要
  - サーバーが受け取るのは抽出テキストと `source_url`（文字列）だけ。`source_url` は表示用の値として扱い、サーバーからアクセスしない
- PDF・画像はサーバーにアップロードしない。ファイルを解析する処理をサーバーに置かない

---

## 9.10 レート制限

- 目的はコスト防御ではなく、乱用の防止（2.10.3）
- `GET /s/{token}`：IP 単位で 1 分あたり 30 回。トークンの総当たりを防ぐ
- 認証が必要な API：user_id 単位で 1 分あたり 120 回
- 超過時は 429 `RATE_LIMITED` と `Retry-After` を返す
- フェーズ1は、Cloud Run のインスタンス内のメモリでカウントする（インスタンス間で共有しない簡易版）

---

## 9.11 ログ・監査

- アプリログ（Cloud Run の構造化ログ。7 章）
  - 個人情報と本文データを出さない（質問・回答・自己資産・ES 本文・メールアドレス・共有トークン）
  - `request_id`、`user_id`（内部 ID）、エンドポイント、ステータス、エラーコード、処理時間を出す
- 監査の対象
  - 共有リンクの発行・失効（`share_links` の created_at / revoked_at）
  - AI連携の状態遷移（`prompt_sessions` の status と各時刻）
  - 退会（`users.deleted_at`）
- 旧設計のクレジット取引・生成ジョブの監査ログは廃止した

---

## 9.12 退会・データ削除

- 退会は `DELETE /me` で行う
- BFF は、1 トランザクションで次を行う（6.3.3）
  - そのユーザーのドメインデータを即時に物理削除する
    - 対象：`users` に紐づく全テーブル（assets・asset_tags・companies・research_materials・es_projects・es_sections・interviews・interview_logs・qa・各関連テーブル・prompt_sessions・share_links・dashboard_summaries）
    - 共有リンクも削除されるため、共有ページは閲覧できなくなる（404）
  - `users` 行は物理削除せず、`deleted_at` を設定し、`email` と `display_name` を消去して残す
- 退会後に古い ID トークンで来たリクエストは 401 として扱う（9.3）
- クライアントは、BFF の退会が成功したあとに次を行う
  - Firebase Auth のアカウントを削除する（BFF は管理者権限の認証情報を持たないため、クライアントが行う）
  - 端末のキャッシュと下書きを消す
- 決済データは存在しないため、会計目的で保持するデータはない

---

## 9.13 規約・法務（最低限）

- 利用規約
  - 外部AIの出力の正確性は保証しない
  - 採用結果は保証しない
  - 不正行為（経歴詐称の助長など）を禁止する
  - 外部AIサービスの利用は、各サービスの規約に従う（ユーザー自身の責任で利用する）
- プライバシーポリシー
  - 収集するデータと利用目的
  - 利用する外部サービス（Firebase / Google Cloud（Cloud Run）/ Neon）
  - 運営側からは外部AIサービスにデータを送らないこと
  - 共有リンクで第三者に公開される範囲
  - 保存期間と削除の手順
- 免責
  - 外部AIの出力は参考情報であり、最終判断はユーザーが行う
- フェーズ1（開発者本人のみの利用）では、規約とポリシーは草案でよい。フェーズ2（TestFlight での配布）の前に確定する

---

## 9.14 この章の凍結事項

- 認証は Firebase Auth。BFF は ID トークンを検証し、user_id はトークンから確定する
- RLS は使わない。全クエリを user_id でスコープし、越境テストを必須とする
- サーバーの秘匿値は `DATABASE_URL` だけ。Firebase の設定は公開情報として扱い、利用制限をかける
- 運営側のサーバーは外部AIにデータを送らない。プロンプトの全文と回答の生データは保存しない
- 共有リンクのトークンはハッシュだけを保存し、期限付き・失効可能・noindex・no-store とする
- URL・PDF・画像の取り込みは端末側で行い、サーバーは外部 URL を取得しない
- 端末のキャッシュは Data Protection で保護し、ログアウト時に消す
- 決済データは扱わない
