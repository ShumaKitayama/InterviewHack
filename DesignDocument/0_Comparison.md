# 0. 企画・前提の固定

> 改訂：2026-10-22。方針転換メモ（`DirectionChange_20261022.md`）の決定事項 D1〜D16 を反映した。

## 0.1 プロダクト名（仮）

- Interview Hack

## 0.2 目的（Purpose）

- 求職者の面接対策を「属人的な反省」から「データとAIに基づく改善ループ」へ転換する
- 面接準備・ES作成・振り返り・復習を1つのアプリ内で完結させ、継続可能な改善サイクルを提供する
- AI はユーザーが普段使っている外部AIサービス（ChatGPT・Gemini など）を活かし、アプリは「材料の整理」「プロンプトの組み立て」「結果の蓄積」を担う（D7）

## 0.3 ゴール（Goals）

### ユーザーゴール

- 面接での受け答えの質を継続的に改善できる状態になる
- 第一志望企業からの内定（転職成功）に近づく

### 事業ゴール（D14）

| 段階 | ゴール |
|------|--------|
| フェーズ1 | 開発者自身の就活・転職で実際に使い切る（ES と面接対策の両方） |
| フェーズ2 | Apple Developer Program に加入し、TestFlight で 10 人前後に使ってもらう |
| フェーズ3 | App Store で公開し、必要なら収益化を検討する |

- 全フェーズを通じて、運営費をほぼ0円に保つ（各サービスの無料枠内で運用する）

## 0.4 ターゲットユーザー

- メインターゲット
  - 新卒就活生・若手転職者
  - ITエンジニア、コンサル、企画職志望など論理性を問われる職種
- 特徴
  - Notion等のツールは使えるが、面接対策の整理・改善が続かない
  - ChatGPT等は使ったことがあるが、毎回プロンプトを組むのが面倒
  - 効率化・仕組み化への関心が高い

## 0.5 想定ペルソナ（例）

- 年齢・属性：21〜28歳、情報系学生または若手社会人
- 行動特性：
  - 面接後に軽くメモは取るが、次回に活かしきれていない
  - 企業ごとに聞かれた質問がバラバラで管理が破綻しがち
  - 改善点を客観的に指摘してくれる存在を求めている
  - iPhone を使っており、ChatGPT や Gemini のアプリを入れている

## 0.6 提供価値（Value Proposition）

- 1面接あたり5分程度の入力で「改善ループ」が回る体験
- 自己資産（経歴・エピソード）と企業情報を一度登録すれば、ワンタップで「そのまま使えるプロンプト」が完成する
  - プロンプトを毎回自分で組む手間がなくなる
- 自己資産（セット1）と企業研究資料（セット2）から、企業別ESドラフトを高速に作成・推敲できる
- 実際の面接ログを元に、一般論ではない「自分専用」の改善案を得られる
- AI の回答がバラバラの会話履歴に埋もれず、Q&A として整理・蓄積され、面接直前の復習に使える
- 追加の利用料がかからない（AI はユーザー自身の外部AIサービスを使う）

## 0.7 コアコンセプト

- 「1面接、5分で完結する改善ループ」
  - 事前準備：自己資産 × 企業情報 → 想定Q&A用のプロンプト → 外部AI → 取り込み
  - 事後改善：実際の回答ログ → 添削用のプロンプト → 外部AI → 改善案の取り込み
  - 復習：蓄積されたQ&Aを単語帳感覚で確認（オフラインでも可）
- AI を使う機能はすべて「AI連携（コピペ方式）」で実現する（1.1.0 参照）

## 0.8 MVPの定義（最小実用プロダクト）

- 必須機能
  - ユーザー登録・ログイン
  - 自己資産DBの登録・編集
  - 企業DBの登録・編集
  - 企業研究資料の取り込み（URL / PDF / 画像）・要約
  - ESドラフト作成・推敲
  - ESの共有リンク（閲覧のみ）
  - 想定Q&Aの作成
  - 面接ログの入力と添削
  - Q&Aの一覧・復習表示
- 非必須（MVPでは入れない）
  - 課金・プラン
  - LLM の API 呼び出し、端末上のLLMによる生成
  - 音声入力
  - 高度な分析ダッシュボード
  - 共有リンクへのコメント、コーチ機能

## 0.9 成功条件（Success Criteria）

- フェーズ1（開発者本人のみ）
  - 定量指標（DB から集計する。D15）
    - テンプレートのバージョンごとの回答の解析成功率
    - AI連携の離脱率（プロンプトを作ったが、回答を貼り戻さなかった割合）
    - 週ごとの Q&A 保存数、復習の回数、面接ログの件数
  - 定性指標
    - 「次の面接で何を直せばいいか分かる」という実感が得られるか
    - Notionやメモ、外部AIの会話履歴に戻らず、このアプリに集約されるか
    - コピペの往復が苦にならないか
- フェーズ2以降
  - 初回登録から「1回以上Q&A保存」まで到達する割合
  - 面接ログ入力→復習までの完了率
  - D7 リテンション

## 0.10 想定利用シーン

- 面接前日・当日朝：想定Q&Aのプロンプトを作り、外部AIの回答を取り込んで確認
- 面接直後：質問と回答を入力し、添削結果を取り込む
- 次の面接前（移動中など、オフラインでも）：過去のQ&Aと改善ポイントを復習
- ES 提出前：友人・メンターに共有リンクを送り、確認してもらう

## 0.11 前提条件

- iPhone 専用のネイティブアプリ（D1）。配布は当面、開発者本人の iPhone のみ（D2）
- プロンプトの作成・回答の取り込み・保存にはネット接続が必要。閲覧・復習・下書きはオフラインでも可能（D16）
- LLM の API を使わず、ユーザーが利用する外部AIサービスとのコピペ連携を前提とする（D7）
- 個人情報・職歴情報という高感度データを扱う

## 0.12 スコープ外（初期ではやらないこと）

- 採用結果の保証や合否予測
- 企業データの自動クローリング（ユーザー操作による1ページ単位の取り込みは行う。D11）
- SNS的な共有・ランキング機能
- 面接代行・回答自動送信などの不正行為支援
